# Paper-cartoon Reel

## Overview

A 20–40 s vertical Instagram Reel told as a tiny cartoon: one character lives through 6–9 scenes, each a new "room" with one idea. **The goal is marketing, not animation**: the video exists to get watched to the end, shared or saved, and to move the viewer to one action. Every decision (hook, story, pacing, CTA, caption) is judged against that.

Three things are decided **fresh for every video**, never inherited from a previous one:
1. **The hook**, generated with marketing/hook skills (Phase 2).
2. **The character**, newly designed (Phase 3).
3. **The palette**, chosen for this topic, mood and audience (Phase 3).

**The voice drives the build**: TTS per sentence, every word timestamped, animations/captions/sound keyed to those words, so sync is exact without hand-tuning.

**Rendering engine: HyperFrames only.** The reel is an HTML + GSAP composition, checked and rendered with `npx hyperframes`. Other tools (Motion, AI video generators, Figma export, editors) may supply *assets* (an image, a sound, a reference) but never assemble or render the reel. Reason: HyperFrames gives a deterministic, seekable timeline, so word-synced captions, stamps and sound land frame-exact; costs no credits per variant; and gives one quality gate (`lint`, `check`, `snapshot`).

This skill is an **orchestrator**. It owns the pipeline and the look; for everything else (research, hooks, copy, sound, review) it pulls in whatever other skills, plugins and MCP tools are installed.

## Use other skills and tools — as many as help, in any order

Before Phase 2, read the list of available skills, plugins and MCP tools. Pick every one that could improve the result — marketing, copywriting, hooks, social, video, animation, design, SEO, research, audio, review, analytics, anything — **any number, any domain, any order**, and repeat a skill whenever a later phase needs it again. Record the picks in `PLAN.md` (skill/tool → what it contributed). Skills inform *content and decisions*; this pipeline does the *building*. For library/API docs use Context7 if installed. Details: `references/tooling-and-voice.md`.

## Workflow

**Phase 0 — Goal (`PLAN.md`).** Fix before anything else: business goal and the single action wanted (comment keyword, follow, DM, click, save), audience and their pain in their words, platform (Instagram Reels, 9:16), language, length, reference videos. Brand colours, fonts and claims are used only if the user supplies a brand; otherwise you choose. Cut references into a contact sheet (`ffmpeg ... fps=2,tile=8x3`) and list per scene: backdrop, props, character role, counters, stamps. Screen recordings at 2× run half as long in reality.

**Phase 1 — Tool sweep.** As above; write the picks into `PLAN.md`.

**Phase 2 — Research and hook.** Follow `references/marketing-and-hooks.md`. The hook is **generated by marketing/hook skills** (use more than one if available), not written off the cuff: audience pain → angle → **10+ hook options from the skills** → score → one primary and one alternate. The hook is scene 1 and must land in the first ~2 s. A greeting, an introduction of the character ("This is Max. He has a website."), a neutral scene-setter or the brand name first is **not a hook**.

**Phase 3 — Story, character, palette, script.**
- Story: 6–9 scenes, ~3–5 s each, one idea each: **hook** → problem shown with objects → turn → how → result → brand + CTA, ending so it loops or invites a replay.
- Character: a new one for this video (`references/look-and-motion.md`, "Characters").
- Palette: your own choice for this video (`references/look-and-motion.md`, "Palette").
- Write `SCRIPT.md` (spoken lines = 4-space-indented lines, one per scene) and `STORYBOARD.md` (per scene: header plaque, backdrop, character role, props, SFX). `assets/example-reel/` shows the file formats only.
- **Show hook options, character, palette, script and storyboard to the user and get approval before building** — the only hard gate. Everything after is cheap to redo; a wrong story is not.

**Phase 4 — Build visuals.**
1. `npx hyperframes init work --non-interactive --resolution portrait` (blank 1080×1920; `--skip-skills` if the user does not want skills installed).
2. Copy `assets/template/*` into `work/`, `assets/template/fonts/*` into `work/assets/fonts/`, plus `PLAN.md`/`SCRIPT.md`/`STORYBOARD.md`.
3. Rewrite the `:root` block of `style.css` (the palette). Rewrite `character.js` (the character). Fonts: Fraunces/Inter are bundled; use others if the look needs it (add `@font-face` to project files).
4. Voice first (Phase 5a), then `python3 scripts/build_index.py --project work --title "<name>" --lang <code>` (re-run after every voice change).
5. Write `work/scenes.js`, one IIFE per scene `n`, with the helpers below. Time every reveal with `W(n,k)` (start of word k in scene n), never fixed seconds. Set `KW` (key words) in `captions.js`. Colours: `var(--token)` in CSS strings, `P("token")` in SVG attributes, never literal hex. Read `references/look-and-motion.md` first; `assets/example-reel/scenes.js` shows structure only: copy no story, character or colours from it.

**Phase 5 — Voice and sound.**
- **5a Voice:** you choose the provider and voice per video; the build only needs `vo.wav` + `vo_timing.json` (format in `references/tooling-and-voice.md`). Bundled: `python3 scripts/gen_vo.py --project work --voice <id>` (Edge TTS, free, word timestamps). Check `TOTAL` against target length; shorten lines or raise `--rate` (+12 % is natural).
- **5b SFX and mix:** use **earshot** (MCP server `earshot` if installed; follow its own skill) to choose, render and verify sounds; it can hear what you cannot. Every popped/stamped/slid element gets a hit; impact lands ~0.15–0.3 s after the animation starts. Built-in fallback: `cues.py` + `python3 scripts/mix.py --project work [--bed music.mp3]` → `assets/audio/mix.wav`, -14 LUFS. Bring your own music; none is bundled.

**Phase 6 — QA gate.**
1. `npx hyperframes lint`, then `npx hyperframes check --json` as the gate (lint, runtime, layout, contrast, craft, audio). Fix every error. A runtime `page_error: X is not defined` means scenes call something `character.js`/`art.js` does not define. Fake-UI text inside props and single-sample entrance overlaps are expected; real text collisions, contrast failures on captions/plaques, and a closing line on screen under ~2 s are not.
2. `npx hyperframes snapshot --at <times inside every scene and mid-animation>` and **look at the contact sheet**: overlaps, empty areas, text outside the safe area, palette contrast.
3. Marketing check: frames 0–2 s show the hook as picture *and* caption; one CTA only; captions ≤3 words; the CTA line stays readable for the last ~2 s.
4. Listen via earshot: `timeline` with `--video` and `--cues` (does each hit land on its cue?), `measure` (loudness, peak), optionally `critique`. Run any review/virality/analysis tool found in Phase 1 on the render.
5. `npx hyperframes preview --background`, check the printed URL answers 200, give the user the Studio project URL and wait for approval, unless they asked for the file or to work without stops.

**Phase 7 — Render and deliver.** `npx hyperframes render --fps 60 --quality delivery --output renders/<name>.mp4` (`--quality draft` while iterating; 60 fps doubles render time, 30 fps is fine for calm reels). Point temp files at a drive with space if the system drive is tight (`TMPDIR`). Verify with `ffprobe` (size, fps, audio track, duration = `data-duration`), `ebur128`, and a frame sheet of the *rendered file*. Deliver to `final/`: MP4, cover JPG (a hook frame), caption in the video's language with hashtags, pinned-comment text, the alternate hook as variant B. Report honestly what was only checked visually or by measurement (not heard by a human) and any length/voice compromises.

## Requirements
Node 22+ (`npx hyperframes`), `ffmpeg`, Python 3 with `numpy`, `python3 -m pip install --target <project>/.pydeps edge-tts` (a current version; old ones get HTTP 403) if the bundled voice script is used. No HyperFrames or HeyGen sign-in needed.

## Helpers (core.js) and factories (art.js)

| Need | Call |
|---|---|
| Entrance animations | `pop(el,t)`, `drop(el,t,y)`, `rise(el,t,y)`, `slide(el,t,x)` |
| Impact | `stamp(el,t,rot,stage,shake)`, `shake(stage,t)`, `bump(el,t)` |
| Number ticker | `count(el,t,dur,from,to)` — works under seeking (uses `snap`, not `onUpdate`) |
| Scene shell | `st=scene(n)`, `paper(st,bg,"dots")`, `hdr(st,n,"TEXT")`, `finish(st)` |
| Character | `character(st,id,x,y,k,{acc:[...]})` (draws your `characterSVG`), `face(id,'n'|'h'|'s'|'z'|'o',t)`, `blink`, `look`, `hop`, `arms`, `wave`, `armsDown`, `idle` |
| Confetti | `confetti(st,t,cx,cy,n,spread)` |
| Props | `siteWin`, `counterCard`, `ICON.*` (recoloured by the palette) |
| Palette | `P("accent-d")` reads a token; palette slots: surfaces `light paper card`, ink `ink muted line`, accent `accent accent-d`, secondary `cool steel`, dark `dark dark2 dark3 dark4`, status `red green gold`, shadow `sh` |

Canvas 1080×1920. Header plaque at y≈150; content between y≈430 and 1440; captions at y 1478. Use `rnd(i)` for pseudo-randomness (no `Math.random`).

## Customizing
New props: add to `ICON` or write a factory in `art.js`. New sound: add a numpy recipe to `S[...]` in `mix.py` and use its name in `cues.py`, or take one from earshot's bank. New language: change voice id, `SCRIPT.md`, `KW`, `--lang`.

## When not to use
Silent/short (<10 s) typographic motion graphics, talking-head edits, product-site tours: use the matching HyperFrames workflow instead. Something breaks: `references/pipeline-gotchas.md`.
